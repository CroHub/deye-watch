# deye-watch

[English](README.md) · **Українська**

Легкий монітор гібридного інвертора **Deye** через Wi-Fi-логер **Solarman LSW-3** (Modbus поверх TCP, локально,
без хмари Solarman) і Telegram-бот для всієї родини:

- ⚡ сповіщення, коли світло зникає і з'являється, — з тим, скільки його не було / було;
- 🔋 попередження «АКБ скоро сяде» (один раз за розряд, без спаму) і прогноз автономії;
- 📊 `/info` — поточний стан: мережа, АКБ, навантаження, споживання за день, температури;
- 🔒 підписка лише зі схвалення власника;
- 🛠 власнику окремо — службові повідомлення (втрата зв'язку з логером, нові запити).

Без Home Assistant і без хмари: один контейнер на будь-якому комп'ютері у вашій домашній мережі.

## Сумісність

| Обладнання | Статус |
|---|---|
| Deye SUN-5K-SG03LP1 + Solarman LSW-3 | ✅ перевірено |
| Інші однофазні низьковольтні гібриди Deye (SG03LP1 / SG04LP1 / SG05LP1, 3.6–12 кВт) та їхні ребрендинги | ❔ мабуть, працюють (та сама карта регістрів), не перевірено |
| Трифазні Deye (SG01HP3, SG04LP3 …) | ❌ інша карта регістрів |

Перевірили на своєму інверторі — напишіть в issue, що працює, а що ні. Для діагностики:
`make dump` виводить сирі регістри (`make dump FROM=150 TO=194` — діапазон).

## Запуск з нуля

### 1. Що потрібно

- Комп'ютер, який працює постійно, **у тій самій локальній мережі, що й логер**: Linux-сервер, Raspberry Pi,
  домашній NAS, старий ноутбук. Найкраще — Linux.
- **Docker** з Compose: <https://docs.docker.com/engine/install/> (перевірка: `docker compose version`).
- **git** і, бажано, **make** (на Debian/Ubuntu/Raspberry Pi OS: `sudo apt install git make`).
  Без `make` теж можна — див. [Команди](#команди).

> На macOS/Windows з Docker Desktop увімкніть **Settings → Resources → Network → Enable host networking**:
> контейнер працює в мережі хоста, щоб бачити логер.

### 2. Завантажити проєкт

```sh
git clone https://github.com/CroHub/deye-watch.git
cd deye-watch
cp .env.example .env
```

Далі всі налаштування — у файлі `.env` (у git він не потрапляє).

### 3. Знайти логер: IP-адреса і серійний номер

- **IP-адреса** — у веб-інтерфейсі роутера, у списку підключених пристроїв (логер зазвичай видно як
  `ESP…`, `LSW…` або за MAC-адресою з наліпки). Бажано закріпити за ним постійну адресу (DHCP reservation),
  інакше після перезавантаження роутера вона може змінитися.
- **Серійний номер логера** — 10 цифр на наліпці LSW-3 (*не* серійний номер інвертора!). Його також видно
  у веб-інтерфейсі логера: відкрийте `http://<IP логера>` (типово логін `admin`, пароль `admin`).

Впишіть у `.env`:

```sh
INVERTER_HOST=192.168.1.50
INVERTER_SERIAL=2712345678
```

Перевірка зв'язку — має показати поточний стан інвертора (перший раз ще збере образ, ~1 хв):

```sh
make info
```

### 4. Створити Telegram-бота

1. Відкрийте в Telegram [@BotFather](https://t.me/BotFather) і надішліть `/newbot`.
2. Введіть назву бота, яку бачитимуть люди, наприклад `Світло вдома`.
3. Введіть username — латиницею, обов'язково із закінченням `bot`, наприклад `my_home_deye_bot`.
4. BotFather надішле **токен** виду `1234567890:AAH...`. Це пароль бота — нікому його не показуйте.

Впишіть у `.env`:

```sh
TELEGRAM_TOKEN=1234567890:AAH...
```

Необов'язково, у тому ж @BotFather: `/setuserpic` — аватарка, `/setdescription` — опис, який бачить людина
перед першим повідомленням.

### 5. Зробити себе власником (адміном) бота

Власник — це один Telegram-акаунт, якому бот довіряє: він схвалює нових користувачів і отримує службові
повідомлення. Бот визначає власника за його **chat_id** — числом, яке треба вписати в `.env`.

1. Відкрийте [@userinfobot](https://t.me/userinfobot) і натисніть **Start** — він відповість вашим `Id`
   (наприклад `123456789`).
2. Впишіть його в `.env`:

   ```sh
   TELEGRAM_ADMIN=123456789
   ```

Без `TELEGRAM_ADMIN` бот працює, але підписатися на нього не може ніхто — схвалювати нікому.

### 6. Інші налаштування (за потреби)

У `.env.example` описані всі параметри з типовими значеннями: ємність АКБ (`BATTERY_KWH`), пороги заряду,
тариф (`TARIFF`), часовий пояс (`TZ`). Розкоментуйте й змініть ті, що відрізняються.

### 7. Запустити

```sh
make run     # збирає образи, проганяє тести, запускає бот у фоні
make logs    # дивитися, що він робить (Ctrl+C — вийти з логів, бот працює далі)
```

Бот запускається з `restart: unless-stopped` — сам підніметься після перезавантаження комп'ютера чи Docker.

### 8. Підписатися

1. Знайдіть свого бота в Telegram за username і натисніть **Start**.
2. Напишіть своє ім'я — ви власник, тож підписку оформлено одразу.
3. Перевірте: `/info` має показати стан інвертора.

Тепер можна давати посилання на бота родині (див. нижче).

## Telegram-бот

**Як підписується інша людина.** Вона відкриває бота, натискає **Start** і пише своє ім'я. Власнику приходить
запит із кнопками **✅ Додати** / **❌ Відхилити**. Після схвалення людина отримує вітання й усі сповіщення.
Відхилених бот далі ігнорує; щоб дозволити повторний запит — видаліть запис із `data/blocked.json`.

**Команди для всіх:** `/info` — поточний стан, `/stop` — відписатися.

**Команди власника** (з'являються в меню лише у нього): `/users` — список користувачів і запитів, що чекають;
`/remove` — видалити користувача (кнопками або `/remove ім'я`).

**Сповіщення:** світло зникло / з'явилося — усім; «АКБ скоро сяде» — усім; втрата зв'язку з логером,
запуск бота — лише власнику, без звуку.

## Команди

```sh
make run                   # зібрати, прогнати тести й лінтер, (пере)запустити бот
make logs                  # логи бота
make stop                  # зупинити бот
make info                  # поточний стан інвертора (разово)
make live                  # живий дашборд у терміналі (make live SEC=2)
make dump                  # сирі регістри (make dump FROM=150 TO=194)
make tg                    # перевірити Telegram: користувачі + тестове повідомлення власнику
make test                  # тести (без інвертора й Telegram)
make lint                  # ruff + mypy strict
make                       # список усіх команд
```

Без `make` — те саме через Docker Compose:

| make | docker compose |
|---|---|
| `make run` | `docker compose up -d --build watch` |
| `make logs` | `docker compose logs -f watch` |
| `make stop` | `docker compose down` |
| `make info` | `docker compose run --rm cli info` |
| `make test` | `docker compose run --rm test` |

## Оновлення

```sh
git pull
make run
```

Дані (`data/`) і налаштування (`.env`) при оновленні зберігаються.

## Архітектура

```
deye/
  model.py          Reading (знімок стану), Battery (запас, автономія), diagnose() — чиста доменна логіка
  config.py         Settings: типові значення + змінні оточення
  clock.py          Clock — абстракція часу (у тестах — FakeClock)
  storage.py        UserStore, GridStateStore — JSON у DATA_DIR з атомарним записом
  inverter/
    registers.py    карта регістрів → Reading
    link.py         Link — постійне з'єднання з логером + одна повторна спроба після розриву
  telegram/
    api.py          TelegramApi — HTTP-транспорт Bot API
    bot.py          TelegramBot — черга надсилання на час без інтернету, прийом оновлень
    message.py      Message, parse_update()
  render/
    format.py       тривалість, шкали заряду
    terminal.py     звіт для терміналу
    telegram.py     звіт /info і тексти подій для Telegram
  watch/
    alarms.py       правила: GridAlarm, LowBatteryAlarm, LinkHealth
    notifier.py     Notifier — усім користувачам / лише власнику
    watcher.py      Monitor (одне опитування), Sleep/BotListener (пауза), Watcher (цикл)
  bot/commands.py   CommandHandler — /info, /stop, /users, /remove, реєстрація зі схваленням власника
  app.py            composition root: збирає залежності
  cli.py            командний рядок (argparse)
```

Принципи:

- **Одна відповідальність** на клас: транспорт Telegram не знає про користувачів, правила сповіщень не знають
  про Telegram (лише про `Notifier`), звіти не знають, звідки взялись дані.
- **Залежності передаються в конструктор** (`Clock`, `Connector`, `BotApi`) і збираються лише в `app.py` —
  тести підставляють фейки без `mock.patch`.
- **Нове правило сповіщень** — клас із методом `check(reading)`, доданий у список `alarms` в `app.py`;
  решту коду змінювати не треба.

## Дані

Створюються автоматично в `data/` (у git не потрапляють):

- `users.json` — підписані користувачі (chat_id → ім'я);
- `requests.json` — запити, що чекають схвалення; `blocked.json` — відхилені;
- `state.json` — останній стан мережі, щоб після перезапуску правильно рахувати, скільки світла немає/є.
